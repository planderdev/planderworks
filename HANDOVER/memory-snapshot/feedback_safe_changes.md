Planderworks에서는 **기능(동작)과 데이터베이스를 절대 건드리지 않는다.** 손상되거나 변경될 여지가 조금이라도 있는 것은 아예 손대지 않는다.

**Why:** 이 앱은 Codex로 만들어졌고(자세한 맥락은 [[project-planderworks]]) 테스트가 전혀 없다. 사용자가 회귀를 매우 경계하며, "손상되거나 변경될수도 있겠다 싶은건 아예 손대지 않는 선에서" 진행하라고 명시적으로 요구함.

**How to apply:**
- 리팩터링/정리 작업은 **동작 보존을 증명할 수 있을 때만** 한다. 가장 강한 증명은 **빌드 산출물 byte-identical** 비교다: `npm run build` 후 `find dist -type f ! -name build-meta.json | sort | xargs shasum | shasum`로 해시를 비교 (build-meta.json은 타임스탬프/커밋이라 제외). 빌드는 결정적이라 같은 소스면 같은 해시가 나온다.
- **타입/인터페이스 선언 분리**는 빌드 시 제거되므로 byte-identical을 유지한다 → 안전. (실제로 src/types.ts로 80개 타입을 빼도 해시 동일 확인됨)
- 런타임 코드(상수/유틸/컴포넌트) 이동은 번들을 바꾸므로 byte-identical로 증명 불가 → 테스트가 없는 상태에선 위험. 진행 전 사용자 동의를 받는다.
- 도구 추가도 빌드에 영향 줄 수 있다: 루트 `tsconfig.json`은 Vite가 자동으로 읽어 esbuild 트랜스파일을 바꾼다(빌드 해시 변함). 그래서 타입체크 설정은 `tsconfig.typecheck.json`으로 분리하고 `tsc -p tsconfig.typecheck.json`으로 호출 → 빌드 무영향.
- 패키지 설치는 auto-mode 분류기가 공급망 리스크로 차단할 수 있다(예: @types/react 설치 거부됨). 우회하지 말고 사용자에게 허가를 구한다.
- **위험한 대량 변경(예: CSS 오버라이드 teardown, 대규모 리팩터) 전엔 검증된 현재 상태를 먼저 로컬 커밋해 백업포인트를 잡고 들어간다.** 사용자가 명시 요청한 원칙. 깨지면 그 체크포인트로 되돌린다. (main=프로덕션 자동배포이므로 체크포인트는 로컬 커밋만, 푸시는 별도 동의 시.)
- **장기 리팩터 작업은 사용자가 "완전 위임"함**("내가 끊을 이유도 없고 나한테 확인받을 이유도 없어"). 즉 확인받지 말고 자율적으로 쭉 진행하고, 위험 지점마다 알아서 로컬 커밋 체크포인트를 찍으며 계속한다. 매 단계 빌드/타입체크 + 프리뷰(:5173) 라이트/다크 스크린샷으로 검증.
- **긴 자율 작업 중엔 중간중간 짧게 진행 상황을 보고**한다("하고 있어요 / 방금 X 했어요"). 사용자가 요청한 안심용 핑. 확인을 구하는 질문이 아니라 상태 핑이다.
